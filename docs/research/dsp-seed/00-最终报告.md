## 0. 结论速览

1. **可以离线从种子算出全星区资源表。**
   - 工具：DoubleUTH/DSP-Seed-Finder（Rust，Apache-2.0）复刻了游戏的 UniverseGen、StarGen、PlanetGen 和矿脉生成，并实现了“实际矿脉量”。
   - 原型：`_过程文件/seed_planets.py` 调用它的本地模式，一个 64 星种子不到 1 秒就能列出全部恒星、行星、每颗行星的矿量与油泉合计、气巨产率和海洋类型。
   - 缺口：它只输出每颗行星每种矿的**总量**，没有矿点数和单个油泉的储量；巢穴数还取决于黑雾设置，原型没有传。结果与游戏是否一致，还没拿存档逐颗对拍（§2.4）。
2. **珍奇“何时、用多少”可以写成对配方选择线性的储量约束。**
   - 原理：矿物利用每级把开采消耗乘以 0.94，研究成本每级多 4000 白糖。从某一级起白糖全部投入矿物利用时，以后累计消耗的储量收敛为 a_r·S(L)，a_r 是每白糖的矿石 r 用量。S(6)≈815 449，是社区已知的结果，笑笑也用过。
   - 约束：对每种有限储量 r（**包括原油**），a_r(x)·S(L) ≤ B_r。原油也是“储量 × 0.94^L”结构，不是可再生资源（§3、§4.1）。
   - 算法与笑笑一致：他的磁石配方（3.28 个/白糖）和储量 142k 代入后得到“80 级后可用”。
   - 研究站喷增产剂会让每级所需白糖 ×0.8（存疑，社区实测），所有阈值整体前移约 4–5 级（§4.1）。
3. **本种子（32 星、0.1 倍）的答案（§4.3）：**
   - 带全部储量约束（含原油）、以最少建筑为目标的 LP，从 L6 起就能无限研究。它靠气巨的氢和重氢替代原油，珍奇用到配额为止。
   - 固定配方时原油会先卡住：原油用得多的配方要到 L19–L40。
   - 珍奇的最优用法是**阈值型**：某一级之前不用，之后放开。磁石放开的等级是 L98（不喷增产，10 个/白糖）或 L77（喷 Mk.III，3.28 个/白糖）；研究站也喷增产时分别为 L94 和 L72。笑笑“早用不如晚用、80 级后放开”正是这个结构。
4. **终局最大白糖/分钟（§5.5）：** 本种子在 L81 时，原料速率在 10 万糖/分（不喷增产）或 20 万糖/分以上（喷 Mk.III）才开始卡。所以真正的上限是戴森球功率，以及作为 UPS 代理的建筑数。
   - 戴森球功率：每 1 白糖/分要 16 MW（喷 Mk.III）到 20 MW 的射线接收功率，两万糖约 320–400 GW，十万糖约 1.6–2 TW。
   - 建筑数：十万糖时仅生产建筑就有 9 万到 21 万座。
   - 原油：初始速率在约两万糖/分时用满，之后由气巨接替。
   - 本种子的戴森球最大功率还算不出来，所以 z 的最终数字还缺这一项。
5. **黑雾会改变答案。**
   - 有限储量约束会部分变成速率约束：单极磁石、光栅石，以及处理器、碳纳米管、粒子容器、反物质等中间品，都可以直接掉落。
   - 矿物利用每级还会把残骸产出提高 4%。
   - 但掉落速率没有公开的定量数据，只能作为待实测的参数源来建模（§5.4）。
6. **建议路线（详见 §9）：**
   1. 接入种子生成器：fork DoubleUTH，暴露逐油泉数据和黑雾设置；网页版直接编成 WASM。
   2. 在 `lp.rs` 里加正式的储量约束，目标产量可作为变量求最大；外层对 L 二分。
   3. 让采集速率随矿物利用等级 L 变化。
   4. 建多星球单期 LP。
   5. 建多期模型：先用外生的等级计划做成纯 LP，再考虑整数。
   6. 加入黑雾源，用实测速率参数化。

## 2. 种子如何决定星区：开源实现调研

### 2.1 生成链

输入是 `galaxySeed`、`starCount`、`resourceMultiplier` 和黑雾参数，依次经过：

1. UniverseGen：恒星的位置、类型和光谱；
2. StarGen：每颗恒星的行星、轨道和主题（ThemeProto）；
3. PlanetGen：地形和高度场，共 algo0–14；
4. 矿脉生成：簇数 × 每簇矿点数 × 每点矿量。

ThemeProtoSet 和 VeinProtoSet 的数据从游戏资源导出。依据是 DoubleUTH 的文件结构 [代码]（`src/data/planet_algorithms/algo0..14.rs`、`theme_proto.rs`、`vein.rs`、`random.rs`），以及 w1w218 的机制文档 `src/docs/mechanics.md` [已开]。

DoubleUTH 代码中的要点（`game_desc.rs`、`star.rs`、`planet.rs`）[代码]：

- **稀有档：** 资源倍率 ≤0.1 时进入稀有档，此时原油 ×0.5，气巨产率 ×0.8。倍率 ≥99.5 视为无限资源。
- **矿点量：** 每个矿点的量为 `opacity × 100000 × resource_coef`，再加减方差、乘 1.1、乘倍率。
  - `resource_coef` 随恒星到母星的距离增大，所以远处恒星矿更多，与笑笑“离母星越远单极磁石越多”的说法一致 [笑笑 BV1oBv1eTEk2]。距离因子为 0.6·7^(d/32)，32 ly 以外改为迭代对数，趋于饱和（`star.rs` 187–199 行）。
  - 系数修正二选一（`planet.rs` 651–660 行）：母星 ×2/3；否则在稀有档里，大于 1 的系数取 ^0.8 再 ×0.7。因此“越远越多”在稀有档里被削弱。
  - 油泉和气巨对距离的反应弱得多：油用 `resource_coef^0.5`（`planet.rs` 705、1106 行），气巨用 `^0.3`（525 行）。w1w218 的 `mechanics.md` 写法相同，并说明约 15% 的油泉会生成在水下 [已开]。
- **实际矿脉量：** 要先生成地形高度场，再剔除没入水下的矿点（`surface_height >= radius`）。
  - botany233 README 说快速模式取理论最大值，实际约为它的 0.8 倍 [已开]。
- **黑雾规模：** 每颗恒星的初始和最大太空巢穴数（`initialHiveCount` / `maxHiveCount`）由种子和黑雾设置（`hive_initial_colonize`、`hive_max_density`）共同决定（`star.rs` 482–520 行）。
  - 原型没有传这两个参数，用的是默认 1.0，所以样例里的 `hives=` 不对应“黑雾全拉满”的存档。
  - 地面基地数不在这些生成器的输出里（存疑，w1w218 从存档读取）。

### 2.3 原型（已跑通）

`_过程文件/seed_planets.py` 只用 Python 标准库。它启动 DoubleUTH 的 `dsp_seed`，通过 websocket 发送 `{"type":"Generate","seed":..,"game":{starCount,resourceMultiplier,useActualVeins}}`，然后输出两部分：

- 逐级列出的“恒星 → 行星 → 矿量 / 气巨产率 / 海洋（水或硫酸）”；
- 全星区各资源的总量。

```
git clone --depth 1 https://github.com/DoubleUTH/DSP-Seed-Finder && cd DSP-Seed-Finder
cargo build --release --bin dsp_seed
python seed_planets.py --bin target/release/dsp_seed.exe --seed 12345678 --stars 32 --mult 0.1 --actual --json g.json
```

样例输出在 `_过程文件/sample_seed12345678_*`。种子 12345678、32 星、0.1 倍、实际矿脉时，全星区总量如下：

| 资源 | 总量 |
|---|---|
| 铁 | 127.8M |
| 铜 | 129.6M |
| 钛 | 114.2M |
| 石 | 65.6M |
| 硅 | 53.3M |
| 可燃冰（地面矿） | 24.6M |
| 煤 | 17.8M |
| 金伯利 | 7.07M |
| 光栅石 | 5.39M |
| 分形硅 | 3.09M |
| 刺笋 | 2.76M |
| 有机晶体 | 1.78M |
| 单极磁石 | 0.18M |
| 原油 | 初始速率合计 404.8/s，分布在 12 颗行星；对应储量 ≈10.12M（见下） |
| 气巨 | 15 颗。基础速率合计：氢 8.48、重氢 0.40、可燃冰 4.21（单位见下） |

单极磁石只出现在中子星（83.9k）和黑洞（97.7k）上。笑笑的存档同为 32 星、0.1 倍，合计约 142k（分项含义存疑）[笑笑 BV1sQBtYxEsm]，与本样例数量级相同。

**单位说明：**
- 矿量是一颗行星上所有矿点之和。
- 原油：生成器里油泉的 `amount` 乘 4e-5 就是初始速率（代码注释“times 4e-5 for oil”），所以全星区油泉储量 ≈ 404.8/4e-5 ≈ 1012 万点。每个油泉有 2500 点（0.1/s）的下限不会采掉，但油泉个数没有输出，这部分扣不掉。
- 气巨的 `gases` 是行星的基础气体速率，已含稀有档的 ×0.8，不是单台采集器的产率。单台毛产 = 8·(1+0.1L)·该值，再扣除 30 MW 的自耗（§3）。

### 2.4 准确性与许可

- **准确性：**
  - DoubleUTH 的测试只防自身回归，我们也没有用存档对拍过，所以“与游戏一致”仍是存疑。
  - w1w218 精算约 27 秒/种子并与存档对拍过，DoubleUTH 约 0.7 s，两者的精度可能不同，因此更需要对拍。
  - 验证办法有两种：在游戏里用同一种子新建存档，核对几颗行星；或者用 w1w218 的存档解析器作外部对拍（GPL，不复制代码）。
  - DoubleUTH 的 README 没有写支持的游戏版本，游戏更新后要重新验证。
- **许可：**
  - DoubleUTH 是 Apache-2.0，可以作为依赖或 vendored 进本仓库，要保留它的 `LICENSE.txt`（仓库里没有 NOTICE 文件）。
  - 它内置的 ThemeProto 等数据导出自游戏，已随 Apache-2.0 仓库和 GitHub Pages 公开发布；数据版权属于游戏方，是否随本项目再分发由 Xinyu 决定。
  - GPL 仓库只能参考思路或作为独立进程调用，不能把代码合进来。

## 4. 关键推导：珍奇“无限阈值”与配额

### 4.1 推导（社区已知结果，此处整理成可求解的形式）

**定义：**
- a_r：每个宇宙矩阵消耗的资源 r，按开采产出计。它取决于配方组合 x 和增产剂。r 包括全部固体矿和**原油**；水、硫酸可以无限抽取，不在其中；气巨按速率约束处理（§5.1）。
- 研究第 n 级（n≥6）需要 C(n)=4000·(n−5)·ρ 个白糖。ρ=1 表示研究站不喷增产，ρ=0.8 表示喷 Mk.III（存疑，§3）。研究这一级期间，开采处在第 n−1 级，每开采 1 单位矿只消耗 0.94^(n−1) 单位储量。
- **S(L)：** 从“已完成 L−1 级、开始研究第 L 级”起，一直研究下去所累计的储量消耗系数（ρ=1 时）：

  **S(L) = Σ_{n≥L} 4000·(n−5)·0.94^(n−1)**

  级数收敛。当 L=6 时有闭式 4000·0.94⁵/0.06² = 815 448.9。研究站喷增产时用 ρ·S(L)。

**判据：** 如果从该时刻起，白糖 100% 投入矿物利用研究、并且永远持续，那么对所有 r 满足 a_r·ρ·S(L) ≤ B_r（B_r 为**剩余**储量）时，储量永不耗尽。

**修正与边界：**
- **采矿速度不影响判据。** 速度每级 +10% 只会加快开采；每开采 1 单位矿消耗多少储量只由 0.94^L 决定。
- **部分白糖另作他用时：** 如果比例 φ 的白糖用于其他科技或用途，判据变为 a_r·ρ·S(L)/(1−φ) ≤ B_r。
- **停止研究时：** 一旦停止矿物利用研究，消耗速率就固定为 0.94^L>0，任何有限储量终将耗尽，除非 390 级真能让消耗归零。到达 390 级累计约需 3 亿白糖。
- **一次性建筑材料也要乘 0.94^L：** 在 L 级时采 K 个矿只扣 K·0.94^L 点储量。判据写成

  U_r + Σ_j K_{r,j}·0.94^{L_j} + a_r·ρ·S(L)/(1−φ) ≤ B_r

  其中 U_r 是早期已经**扣掉的储量**（不是用掉的物品数），K_{r,j} 是第 j 批建筑用料，L_j 是开采那批料时的等级。
  - 例：位面熔炉每台 15 个单极磁石（由它升级的负熵熔炉间接继承），笑笑估计两万糖厂需要约 45000 个 [笑笑 BV1wxikYXEHp]。在 L20 采这些磁石扣 1.31 万储量，L40 扣 3800，L80 只扣 319。
  - 所以建筑用的珍奇同样是越晚采越省。到终局，它们相对 a_r·S(L) 可以忽略。
- **按时间消耗的物品：** 引力透镜（接收站每台 0.1/min）、空间翘曲器、防御弹药、黑雾防线补塔等，消耗正比于时间而不是白糖数。研究第 n 级耗时 C(n)/z，所以判据还要加一项 (c_r/z)·ρ·S(L)，c_r 是每分钟的这类消耗，z 越小越吃亏。规划器把临界光子当原料，透镜消耗目前不在 a_r 里。

### 4.2 与笑笑的算法一致

- 笑笑用的 S=815448 [笑笑 BV1sQBtYxEsm] 就是上面的 S(6)，模型相同。
- 他的磁石用量为每白糖 3.28 个，储量 142k。代入判据，第一个满足 3.28·S(L) ≤ 142k 的是 **S(81)=43 286**（3.28×43 286 = 141.98k），也就是“完成 80 级后可以放开用磁石”，与他的 L80 结论一致 [笑笑 BV1sQBtYxEsm]。
- 他的刺笋阈值约为 L49，与上表结构一致。

### 4.3 用现有规划器实测

脚本与输出：`_过程文件/rawpercube_main.rs` → `rawpercube_output.txt`（固定配方的原料表），`rawpercube2_main.rs` → `rawpercube2_output.txt`（带储量约束的阈值扫描）。

做法：在临时 crate 里调用本仓库的 `planner::plan`。目标为 1 白糖/min，连续 LP，允许全部替代配方，不用黑雾物品。

**(1) 固定配方的每白糖原料（对照用）。**

- 情形 A：资源权重全为 1，允许珍奇，不用增产剂。
- 情形 E：权重人为设为 1/星区储量，原油、水、硫酸、氢、重氢、光子的权重设为 0.001。
- 情形 F：E 的权重 + 增产剂 Mk.III（额外产出）。

E、F 的权重是人为设定的：1/储量这个权重不管用量离上限多远，都重罚珍奇，同时让原油几乎免费。所以它们“避开全部固态珍奇”是权重造成的，不是种子的性质。

**(2) 带储量约束的 LP（主结果）。**

- 约束：对每级 L，每种有限资源（12 种固体矿 + 原油）的每白糖用量 ≤ B_r/(ρ·S(L))。
- 目标：最少建筑数。

结果：

- **从 L6 起就可行**，喷不喷增产、研究站 ρ=1 或 0.8 都一样。此时原油只用 2 个/白糖（喷 Mk.III 时 0.66），2×S(6)=163 万，远在原油储量以内。LP 用气巨的氢（约 9–11/白糖）和重氢（5/白糖）替代原油，珍奇用到配额为止。
- 如果没有气巨可用（把氢、重氢设为 0），LP 改用更多光子（不喷增产时 20 光子/白糖），代价落在戴森球功率上。

**(3) 三层答案（本种子：32 星，0.1 倍，开局储量）。**

1. **能否无限研究：** 能，从 L6 起。条件是能用气巨的氢和重氢（或多花光子），而且原油要按储量算进约束。只看固定的原油配方，要到 L19（A）、L25（F）或 L40（E）。
2. **配额的含义：** B_剩余/S(L) 是“从这一级起永远按这个量用也不会用完”的**安全上限**，不是建议用量。
   - 同一份储量不能在几级里各用一次满额。分级使用时，正确的滚动配额是 B_剩余(当时)/S(L)。
   - 早用一个珍奇和晚用一个，收益（省建筑、省原油）相同，储量成本却是 0.94^(n−1)，随等级下降。所以在约束 Σ_n C(n)·0.94^(n−1)·a_r(x_n) ≤ B_r 下，这是一个分数背包，收益/成本比随 n 递增。最优解是**阈值型**：某一级 L* 之前不用，之后按最大用量放开。
   - 笑笑的“早用不如晚用、80 级后放开”正是这个最优结构。只有当早期另有硬约束被珍奇缓解时（例如建筑数上限、早期原油速率），早用才可能进入最优解，这要由带时间目标的多期模型判断（§5.2）。
3. **完全放开的阈值（单极磁石，B=0.182M）：**

| 配方 | 每白糖磁石 | ρ=1 | ρ=0.8（研究站喷 Mk.III） |
|---|---|---|---|
| 不喷增产（情形 A / 最少建筑） | 10 | L98（累计 1711 万白糖） | L94（累计 1253 万） |
| 喷 Mk.III（最少建筑，同笑笑配方） | 3.28 | L77（累计 1022 万） | L72（累计 707 万） |

注意事项：
- B_r 应取**剩余**储量。开局总量没有扣掉 L1–5 期间和早期建造的消耗，也没有扣掉被黑雾占据、暂时拿不下的星球。
- 在玩的存档应从存档里解析剩余储量（§7）。
- 每白糖的原矿量依赖 `data/dsp.json`（0.10.29）的配方，不是游戏实测值。

## 5. 优化建模

### 5.1 单期、多星球模型的组成

**集合：** 星球 p（含气巨）、物品 i、配方 r、资源类型 k。

**生产变量：**
- 配方运行量 x_{r,p} ≥ 0；需要整台建筑时另设 n_{r,p} ∈ ℤ⁺，沿用 lp.rs 的整建筑写法。

**开采变量与上限：**
- 固态矿：m_{k,p} ≤ 矿机台数 × 每台速率 × (1+0.1L)。矿点数可以作为矿机布置的上限，但生成器目前不输出矿点数（§2.2）；而且矿机覆盖范围可以重叠，同一矿点能否被多台矿机同时开采还要在游戏里核实（存疑）。所以这里先按矿机数和占地来限制。
- 原油：储量进入 §4 的储量约束。速率方面，每个油泉介于下限 0.1·(1+0.1L)/s（存疑）与初始速率 ×(1+0.1L) 之间，并受单台 7200/min 限制。采到下限后的长期速率是 N_seep×0.1·(1+0.1L)/s，N_seep 要等生成器输出逐油泉数据。
- 气巨：每颗气巨的台数 c_p ≤ 40，每台净产为 g_{p,i}(L) = 毛产·(1+0.1L) − 自耗。
- 海洋：50·(1+0.1L)/min × 抽水站台数。

**运输：** 流量 f_{i,p→q} ≥ 0。
- 星际运输成本可以线性计入：翘曲器消耗加运输船电力。翘曲器每趟 1 个，仅当距离超过启用曲速的距离（存疑）。
- 运力受物流塔数和运输船数限制。

**物料平衡（每个 p、i）：** 配方净产出 + 开采 + 气巨 + 海洋 + 黑雾掉落 + 运入 − 运出 = 需求。

**能量：** 各星球的耗电 ≤ 本地发电 + 星际输电（能量枢纽）+ 射线接收站。光子源受各恒星戴森球功率的限制，P_star 正比于光度 × 球规模，可以作为外生参数输入。

### 5.2 问题 (a)：早期多期模型

时间分为 t=1..T 段，每段 1–3 h。

**科技解锁：**
- 二值变量 u_{τ,t} 单调不减，累计研究量 ≥ 成本时才能取 1。
- 配方和建筑的使用受其约束：x_{r,p,t} ≤ M·u_{τ(r),t}。M 要取紧（按该配方在本时段的可能最大产量），否则松弛极差。

**储量动态：**
- B_{k,p,t+1} = B_{k,p,t} − Δt·0.94^{L_t}·m_{k,p,t}。
- 等级 L_t 是累计投入矿物利用的白糖的阶梯函数。线性化有两种办法：
  - 把各时段的等级当作外生计划；
  - 用 one-hot 二值或 SOS1 选择等级，再乘以预先算好的系数。

**终端储备约束：** 这是回答“早期用多少珍奇”的核心。它把早期使用和终局可持续性连在一起：
- 单一配方时：B_{k,T} ≥ Σ_j K_{k,j}·0.94^{L_j} + a_k(x_end)·ρ·S(L_T)/(1−φ)；
- 分级配方时（§4.3）：B_{k,T} ≥ Σ_j K_{k,j}·0.94^{L_j} + Σ_{n≥L_T} C(n)·0.94^(n−1)·a_k(x_n)/(1−φ)。

**目标：** 最少时间到达目标科技，或者在给定时间内累计研究量最大。珍奇用多少是优化的结果，不是目标本身。只有这类带时间的目标才能判断“早期少量用珍奇”是否优于 §4.3 的阈值策略。

**求解路线：**
- 先做不含整数的版本：等级计划作为外生输入，科技解锁顺序固定。这样模型退化成 LP，microlp 就能解。
- 带 big-M 解锁、等级 one-hot 和多星球的完整 MILP 超出 microlp 的能力（它的分支定界很基础，现有 `lp.rs` 靠时间上限兜底），只适合离线用 HiGHS。

**规模控制：** 只保留母星系和少数候选星系，按恒星系聚合星球。

### 5.3 问题 (b)：终局稳态

**目标：** 在给定 L 时 max z（白糖/min）。

**约束：**
1. 物料平衡，开采与采集上限随 L 放大（§5.1）。
2. **可持续：** a_k(x)·ρ·S(L)/(1−φ) ≤ B_k − U_k − Σ_j K_{k,j}·0.94^{L_j}，对所有有限储量 k（含原油）。在稳态里这条约束对配方选择的限制，和 §4 的配额是同一件事。它对 (原料用量, z) 是线性齐次的，可以直接写成 a_k·z·ρ·S(L) ≤ (剩余储量)·z 的形式进 LP。
3. **光子与能量：** 每个白糖要 1 个反物质，所以 z ≤ 光子产率（扣除反物质路线损耗）+ 黑雾掉落的反物质。光子产率受各恒星戴森球功率限制，每 1 白糖/min 约需 16–20 MW 射线接收功率（§5.5）。
   - 笑笑估算两万糖要光子 324 GW、全厂 474 GW [笑笑 BV1wxikYXEHp，转写数字]。按 0.8 光子/白糖 × 1200 MJ/光子独立算得 320 GW，吻合（2700 台接收站 × 120 MW = 324 GW）。
   - 人造恒星的黄棒每根 72 GJ，1 根/min = 1.2 GW。按此，笑笑提到的 300 根/min 约为 360 GW。
4. **原油、气巨的速率：** 原油初始速率 404.8×(1+0.1L)/s，之后衰减到下限；气巨按 40 台/颗的净产。替代路线（气巨的氢和重氢、可燃冰、更多光子）交给 LP 选择。本种子的数字见 §5.5。
5. **一次性建筑材料：** Σ_j K_{k,j}·0.94^{L_j} ≤ 剩余储量 + 黑雾的累计掉落。
6. **实用上限：** 总建筑数 ≤ N_max，物流塔数 ≤ S_max，作为 UPS 的代理。笑笑认为十万糖的最大瓶颈是 CPU [笑笑 BV1wxikYXEHp]。

**结论：**
- 给定 L 时，问题是良定的。理论上限由光子（戴森球）、可再生原料速率（随 L 增长）和黑雾掉落决定。
- 但 L 是随时间累积的状态，不能当作自由变量。
- 实际答案需要选一种写法：
  - (i) 给定 L 和 UPS/建筑上限，求 max z；
  - (ii) 在时间窗 T 内，求累计白糖最多（此时 L 内生）。

### 5.4 黑雾作为源

**建模：**
- 每个可养殖的地面基地 b 设整数或二值变量 y_b，掉落速率向量记为 d_{b,i}(lv, L)。
- 普通物品的掉落按 (1+0.04L)·clamp(资源倍率, 0.3, 2)·(1−缺乏症折减) 缩放；专属物品不受资源倍率影响 [BWIKI，Saros readme]。
- 掉落只出现在解锁等级以上（§3）；已解锁设备、未解锁配方的物品只能拾取 40%。

**成本：**
- 防御塔的建筑数和电力。笑笑的做法是在基地外圈布置激光塔，每排约 10 座 [笑笑 BV1BxDQYyEfU]。
- 行星护盾和轨道炮。
- 拾取上限：每个战场分析基站拾取 8 种物品 [笑笑；BWIKI 战场分析基站页“如需要多于8种材料，推荐多摆几个基站”为旁证]；残骸 3 分钟不拾取就消失（存疑）。
- 威胁度和太空袭击，可以先按固定成本计。

**数据缺口：**
- 掉落速率没有公开的定量数据。BWIKI 只有解锁表；笑笑只说“单极磁石掉落速度还是非常慢”“超频越多掉的磁石就越多” [笑笑 BV1BxDQYyEfU, BV1wxikYXEHp]。
- 需要在游戏里实测：对一个超频基地记录 1 小时的入库量，并记下当时的黑雾等级和矿物利用等级 L。
- 可养殖的地面基地数是存档状态：地面基地由太空巢穴派中继站落地建成，数量随时间变化，不是“巢穴数 + 基地数”的相加关系。它的上限与该星系巢穴数和行星数有关，具体规则未核实（存疑）。笑笑养的是地面基地。

**对答案的影响：**
- **(a) 早期珍奇：** 单极磁石、光栅石变为可再生，§4 的阈值下降甚至消失。处理器、碳纳米管、粒子容器（笑笑所说“阴间三样”的主体）等中间品可以直接掉落，影响比“磁石可再生”更大。
- **(b) 终局：**
  - 核心素和物质重组器只能来自黑雾，所以黄棒供电和若干配方都依赖它。
  - 掉落的反物质能绕开 §5.3 第 3 条的光子上限。
  - 黑雾凭空产出物品，能抬高 z，抬高多少取决于实测速率、养殖规模，以及 UPS 上限。
- **规划器现状：** `data/dsp.json` 只把 df-* 专属物品列为原料。情形 G（df-* 几乎免费）与情形 F 结果相同，只能说明这些专属物品不在白糖链上，不能说明黑雾对白糖链无关。黑雾掉落的普通物品和中间品目前还不能作为来源（§6）。

### 5.5 样例种子的终局量级估计

脚本与输出：`_过程文件/rawpercube2_maxz.rs` → `rawpercube2_maxz_output.txt`。

**设定：**
- 种子 12345678、32 星、0.1 倍，正在研究 L81，开采处在 80 级，速度 ×9。
- 储量约束：§4 的配额 z·B_r/S(81)，原油储量按 1012 万。
- 速率上限：
  - 原油 ≤ 初始速率 404.8×9 = 3643/s。这是上界，油泉会衰减到未知的下限。
  - 15 颗气巨各 40 台采集器，扣除 30 MW/台的自耗（按热值 氢 8、重氢 9、可燃冰 4.8 MJ 分摊，热值存疑）后净产：氢 22 860/s、重氢 1080/s、可燃冰 11 094/s。
- 光子、水、硫酸不设上限，目标是光子最少。

**结果：**

| z（白糖/min） | 不喷增产：光子/白糖 | 射线接收功率 | 生产建筑数 | 喷 Mk.III：光子/白糖 | 射线接收功率 | 生产建筑数 |
|---|---|---|---|---|---|---|
| 1 000 | 1.0 | 20 GW | 3.1k | 0.8 | 16 GW | 1.7k |
| 20 000 | 1.0 | 400 GW | 53k | 0.8 | 320 GW | 35k |
| 50 000 | 1.0 | 1.0 TW | 102k | 0.8 | 0.8 TW | 57k |
| 100 000 | 1.0 | 2.0 TW | 215k | 0.8 | 1.6 TW | 93k |
| 200 000 | 9.1 | 36 TW | 467k | 0.8 | 3.2 TW | 194k |

**解读：**
- 原油在约两万糖/分时用满初始速率，之后 LP 转向气巨的氢、重氢和可燃冰。原油不是本种子的终局瓶颈。
- 不喷增产时，原料速率在 10 万到 20 万糖/分之间用尽，再往上只能用光子硬换（9.1 光子/白糖）。喷 Mk.III 时到 20 万糖/分仍未用尽。
- 所以本种子在 L81 时，z 实际由两件事决定：
  - 戴森球能提供的功率：每 1 白糖/min 需 16–20 MW，不含引力透镜。
  - 建筑数：表中只计生产建筑，矿机、采集器和物流塔还要另加。
- 缺的数：本种子各恒星的戴森球最大功率。生成器给了光度和戴森球半径，但没有算满球功率，这一项要另建模型。

- 多期、多星球的 MILP 规模远超 microlp（纯 Rust 实现，适合中小规模）。

- 网页端可用 `lovasoa/highs-js`（MIT），它是 HiGHS 的 WASM 构建。调用方式是在 JS 侧把模型以 LP 文本传过去。

## 8. 前置知识（建议学习）

1. **线性规划与对偶：** 物料平衡 LP；影子价格，即规划器的 Item values 页签。珍奇在配额以内时影子价格为 0，这是“稀缺度不能用 1/储量当权重”的原因。参考 Bertsimas & Tsitsiklis《Introduction to Linear Optimization》第 1–4 章。
2. **分数背包与贪心最优性：** 收益/成本比单调时最优解是阈值型，这是 §4.3 “晚用优于早用”的依据。
3. **MIP 建模技巧：** big-M（以及 M 取大时松弛变差）、用 one-hot 或 SOS1 线性化离散等级、分段线性。参考 Williams《Model Building in Mathematical Programming》。
4. **多期规划与库存模型：** 储量状态方程和终端条件。§4 的储备约束就是一种终端价值约束。
5. **几何级数：** Σ k·q^k = q/(1−q)²，由此得到 S(6) 的闭式。
6. **网络流：** 多星球运输是多商品流问题。
7. **程序化生成的确定性复现：** 种子伪随机数生成器（复刻 .NET 的 `System.Random`）、单精度浮点一致性、Simplex 噪声。可以读 DoubleUTH 的 `src/data/random.rs` 和 `planet.rs`，以及 w1w218 的 `src/docs/mechanics.md`。
8. **DSP 机制：** §3 所列的 BWIKI 页面；笑笑的珍奇和万糖视频（第 12、16–20 期）。

## 10. 存疑清单

- 研究站喷增产剂是否让每级所需白糖 ×0.8（影响所有阈值，优先核实）。
- 原油每采 1 个扣多少储量（0.1 倍档按 1 点、1 倍档约 0.4 点，由半衰期反推），以及油泉下限和衰减速度随 L 变化的推论。
- 油泉个数 N_seep（生成器未输出），因此原油储量只有上界、长期下限速率未知。
- DoubleUTH 的“实际矿脉量”与游戏是否一致，以及它支持的游戏版本。
- 本种子各恒星的戴森球最大功率（§5.5 的 z 还缺这一项）。
- 同一矿点能否被多台矿机同时开采；启用曲速的距离。
- 气巨燃料热值（氢 8、重氢 9、可燃冰 4.8 MJ）与自耗扣除方式。
- 黑雾掉落速率（完全没有数据）；黑雾残骸 +4%/级是相加还是相乘；残骸 3 分钟消失；地面基地数的上限规则。
- 两万糖规模的数字（45000 磁石、324/474 GW、300 黄棒/min）和笑笑的 3.28 个/白糖都来自 whisper 转写。
- §4.3、§5.5 的每白糖原矿量依赖 `data/dsp.json`（0.10.29），木材和植物燃料没有储量，不是游戏实测值。
