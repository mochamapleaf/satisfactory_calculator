## 0. 结论速览

1. **可以离线从种子算出全星区资源表。**
   - 工具：DoubleUTH/DSP-Seed-Finder（Rust，Apache-2.0）复刻了游戏的 UniverseGen、StarGen、PlanetGen 和矿脉生成，并实现了“实际矿脉量”。
   - 原型：`_过程文件/seed_planets.py` 调用它的本地模式，一个 64 星种子不到 1 秒就能列出全部恒星、行星、矿量、油泉、气巨产率和海洋类型。
   - 未验证：结果与游戏是否一致，还没拿游戏存档逐颗对拍（§2.4）。
2. **珍奇“何时、用多少”可以直接接入现有 LP。**
   - 原理：矿物利用每级把开采消耗乘以 0.94，研究成本每级多 4000 白糖。只要从某一级起把白糖全部投入矿物利用，以后累计消耗的储量就收敛为 a_r·S(L)，其中 a_r 是每白糖的矿石 r 用量。S(6)≈815 449，是社区已知的结果，笑笑也用过。
   - 本报告的贡献：把它写成对配方选择线性的约束 a_r(x)·S(L) ≤ B_r，再用现有规划器加外层循环求解（§4）。
   - 验证：用笑笑的磁石配方（3.28 个/白糖）和他的储量 142k 代入，复现出他的“80 级后可用”。
   - 结论：在 L 级以前也可以少量使用珍奇，配额为每白糖 ≤ B_r/S(L)。
3. **终局最大白糖/分钟是良定问题，但答案远超实际 CPU 能承受的规模。**
   - 给定矿物利用等级 L，z 受以下几项硬约束：
     - 戴森球光子，每个白糖要 1 个反物质，反物质来自临界光子；
     - 气巨、油泉、抽水站的产率，均随 L 放大；
     - 一次性稀缺材料；
     - 黑雾掉落。
   - 种子样例在 0.1 倍档下，原油很可能是硬约束（§5.3）。
   - 实际可行的答案还要加建筑数或物流塔数上限，作为 UPS 的代理。
4. **黑雾会改变答案。**
   - 有限储量约束会部分变成速率约束：单极磁石、光栅石，以及处理器、碳纳米管、粒子容器、反物质等中间品，都可以直接掉落。
   - 矿物利用每级还会把残骸产出提高 4%。
   - 但掉落速率没有公开的定量数据，只能作为待实测的参数源来建模（§5.4）。
5. **建议路线（详见 §9）：**
   1. 接入种子生成器。
   2. 实现“无限阈值 / 珍奇配额”功能。
   3. 让采集速率随矿物利用等级 L 变化。
   4. 建多星球单期 LP。
   5. 建多期 MILP，处理早期规划。
   6. 加入黑雾源，用实测速率参数化。

## 2. 种子如何决定星区：开源实现调研

### 2.1 生成链

输入是 `galaxySeed`、`starCount`、`resourceMultiplier` 和黑雾参数，依次经过：

1. UniverseGen：恒星的位置、类型和光谱；
2. StarGen：每颗恒星的行星、轨道和主题（ThemeProto）；
3. PlanetGen：地形和高度场，共 algo0–14；
4. 矿脉生成：簇数 × 每簇矿点数 × 每点矿量。

ThemeProtoSet 和 VeinProtoSet 的数据从游戏资源导出。依据是 DoubleUTH 的文件结构 [代码]（`src/data/planet_algorithms/algo0..14.rs`、`theme_proto.rs`、`vein.rs`、`random.rs`），以及 w1w218 README 中“从 galaxySeed 复现恒星/行星/主题/地形/矿脉”一句 [已开]。

DoubleUTH 代码中的要点（`game_desc.rs`、`star.rs`、`planet.rs`）[代码]：

- **稀有档：** 资源倍率 ≤0.1 时进入稀有档，此时原油 ×0.5，气巨产率 ×0.8。倍率 ≥99.5 视为无限资源。
- **矿点量：** 每个矿点的量为 `opacity × 100000 × resource_coef`，再加减方差、乘 1.1、乘倍率。
  - `resource_coef` 随恒星到母星的距离增大，所以远处恒星矿更多，与笑笑“离母星越远单极磁石越多”的说法一致 [笑笑 BV1oBv1eTEk2]。
  - 稀有档会把大于 1 的系数取 ^0.8 再 ×0.7，母星再 ×2/3；32 ly 以外距离因子趋于饱和（`star.rs` 187–199 行）。因此“越远越多”在稀有档里被削弱。
- **实际矿脉量：** 要先生成地形高度场，再剔除没入水下的矿点（`surface_height >= radius`）。
  - botany233 README 说快速模式取理论最大值，实际约为它的 0.8 倍 [已开]。
- **黑雾规模：** 每颗恒星的初始和最大太空巢穴数（`initialHiveCount` / `maxHiveCount`）由种子决定。
  - 地面基地数不在这些生成器的输出里（存疑，w1w218 从存档读取）。

### 2.3 原型（已跑通）

`_过程文件/seed_planets.py` 只用 Python 标准库。它启动 DoubleUTH 的 `dsp_seed`，通过 websocket 发送 `{"type":"Generate","seed":..,"game":{starCount,resourceMultiplier,useActualVeins}}`，然后输出两部分：

- 逐级列出的“恒星 → 行星 → 矿量 / 气巨产率 / 海洋（水或硫酸）”；
- 全星区各资源的总量。

```
git clone --depth 1 https://github.com/DoubleUTH/DSP-Seed-Finder && cd DSP-Seed-Finder
cargo build --release --bin dsp_seed
python seed_planets.py --bin target/release/dsp_seed.exe --seed 12345678 --stars 32 --mult 0.1 --actual --json g.json
```

样例输出在 `_过程文件/sample_seed12345678_*`。种子 12345678、32 星、0.1 倍、实际矿脉时，全星区总量如下：

### 2.4 准确性与许可

- **准确性：**
  - DoubleUTH 的测试只防自身回归，我们也没有用存档对拍过，所以“与游戏一致”仍是存疑。
  - 速度差距也值得注意：w1w218 精算约 27 秒/种子，DoubleUTH 约 0.7 s，两者的精度可能不同，因此更需要对拍。
  - 验证办法有两种：在游戏里用同一种子新建存档，核对几颗行星；或者用 w1w218 的存档解析器作外部对拍（GPL，不复制代码）。
  - DoubleUTH 的 README 没有写支持的游戏版本，游戏更新后要重新验证。

## 4. 关键推导：珍奇“无限阈值”与配额

### 4.1 推导（社区已知结果，此处整理成可求解的形式）

**定义：**
- a_r：每个宇宙矩阵消耗的矿石 r，按开采产出计。它取决于配方组合 x 和增产剂。
- 研究第 n 级（n≥6）需要 C(n)=4000·(n−5) 个白糖；研究这一级期间，开采处在第 n−1 级，每开采 1 单位矿只消耗 0.94^(n−1) 单位储量。
- **S(L)：** 从“已完成 L−1 级、开始研究第 L 级”起，一直研究下去所累计的储量消耗系数：

  **S(L) = Σ_{n≥L} 4000·(n−5)·0.94^(n−1)**

  级数收敛。当 L=6 时有闭式 4000·0.94⁵/0.06² = 815 448.9。

**判据：** 如果从该时刻起，白糖 100% 投入矿物利用研究、并且永远持续，那么对所有 r 满足 a_r·S(L) ≤ B_r（B_r 为**剩余**储量）时，储量永不耗尽。

**修正与边界：**
- **采矿速度不影响判据。** 速度每级 +10% 只会加快开采；每开采 1 单位矿消耗多少储量只由 0.94^L 决定。
- **部分白糖另作他用时：** 如果比例 φ 的白糖用于其他科技或用途，判据变为 a_r·S(L)/(1−φ) ≤ B_r。
- **停止研究时：** 一旦停止矿物利用研究，消耗速率就固定为 0.94^L>0，任何有限储量终将耗尽，除非 390 级真能让消耗归零。到达 390 级累计约需 3 亿白糖。
- **要另加一次性建筑材料 K_r：** 例如负熵熔炉每台 15 个单极磁石，笑笑估计两万糖厂需要约 45000 个 [笑笑 BV1wxikYXEHp]。判据变为 U_r + K_r + a_r·S(L)/(1−φ) ≤ B_r，其中 U_r 是早期已经用掉的量。
- **研究站增产（存疑）：** 如果研究站喷增产剂（额外产出）后每个白糖多产哈希，每级所需白糖会减少，S 也随之按比例变小。

**数值表：**

| L | 6 | 20 | 40 | 49 | 60 | 77 | 81 | 85 | 98 | 100 |
|---|---|---|---|---|---|---|---|---|---|---|
| S(L) | 815 449 | 630 964 | 302 425 | 204 069 | 122 368 | 53 022 | 43 286 | 35 270 | 17 923 | 16 128 |

**到达第 L 级所需的累计白糖** = Σ_{n=6}^{L−1} 4000(n−5) = 2000·(L−6)(L−5)：

| 起研等级 | 累计白糖 | 750 糖/min 时 | 两万糖/min 时 |
|---|---|---|---|
| L81 | 1140 万 | 约 253 h | 约 9.5 h |
| L98 | 1711 万 | 约 380 h | 约 14 h |

这些时间就是“何时能用”的时间换算。

### 4.2 与笑笑的结论对照（独立复现）

- 笑笑用的 S=815448 [笑笑 BV1sQBtYxEsm] 就是上面的 S(6)，模型相同。
- 他的磁石用量为每白糖 3.28 个（转写中的“328”），储量 142k。代入判据，第一个满足 3.28·S(L) ≤ 142k 的是 **S(81)=43 286**（3.28×43 286 = 141.98k），也就是“完成 80 级后可以放开用磁石”，与他的 L80 结论一致 [笑笑 BV1sQBtYxEsm]。
- 他的刺笋阈值约为 L49，与上表结构一致。

**三层答案（本种子：32 星，0.1 倍，开局储量）：**

1. **不用固态珍奇也能无限研究。** 以情形 E 手算 a_r·S(6)：铁 23.6M、硅 22.8M、铜 13.0M、钛 14.7M、石 3.3M，均小于储量。阈值测试（每种有限矿的上限设为 B_r/S(L)，原油、水、硫酸不设上限）在 L=6 即可行，与此一致。
2. **早期配额。** 在 L 级时，每白糖最多可用 B_r/S(L) 个珍奇 r。以单极磁石为例：L6 时 0.22 个，L50 时 0.93 个，L81 时 4.2 个。因此磁石不必等到某一级才开始用，可以从一开始少量用起。
3. **完全放开用的阈值。** 情形 A 的磁石配方（10 个/白糖）要到 S(L) ≤ 18 000，也就是**完成 97 级后（S(98)）**。换成笑笑的配方（3.28 个/白糖），本种子在 **L77** 就可以放开。

**更优的写法：** 允许每一级 n 选不同的配方组合 x_n，约束为 Σ_n C(n)·0.94^(n−1)·a_r(x_n) ≤ B_r。它仍然是线性的，而单一配方的 a_r·S(L) 只是这个约束的一个可行特例（§5.2）。

注意事项：
- B_r 应取**剩余**储量。开局总量没有扣掉 L1–5 期间和早期建造的消耗，也没有扣掉被黑雾占据、暂时拿不下的星球。
- 在玩的存档应从存档里解析剩余储量（§7）。
- 每白糖的原矿量依赖 `data/dsp.json`（0.10.29）的配方和这里设定的权重，不是游戏实测值。

## 5. 优化建模

### 5.1 单期、多星球模型的组成

**集合：** 星球 p（含气巨）、物品 i、配方 r、资源类型 k。

**生产变量：**
- 配方运行量 x_{r,p} ≥ 0；需要整台建筑时另设 n_{r,p} ∈ ℤ⁺，沿用 lp.rs 的整建筑写法。

**开采变量与上限：**
- 固态矿：m_{k,p} ≤ 矿机台数 × 每台速率 × (1+0.1L)。矿点数 Nodes_{k,p} 可以作为矿机布置的上限。不过矿机覆盖范围可以重叠，同一矿点能否被多台矿机同时开采还要在游戏里核实（存疑），所以这里按矿机数和占地来限制，而不是按矿点数。
- 原油：每个油泉的速率介于下限 0.1·(1+0.1L)/s（存疑）与初始速率 ×(1+0.1L) 之间，并受单台 7200/min 限制。稳态取保守下限，也可以按时段衰减建模。
- 气巨：每颗气巨的台数 c_p ≤ 40，每台净产为 g_{p,i}(L) = 毛产·(1+0.1L) − 自耗。
- 海洋：50·(1+0.1L)/min × 抽水站台数。

**运输：** 流量 f_{i,p→q} ≥ 0。
- 星际运输成本可以线性计入：翘曲器消耗加运输船电力。翘曲器每趟 1 个，仅当距离超过启用曲速的距离（存疑）。
- 运力受物流塔数和运输船数限制。

**物料平衡（每个 p、i）：** 配方净产出 + 开采 + 气巨 + 海洋 + 黑雾掉落 + 运入 − 运出 = 需求。

**能量：** 各星球的耗电 ≤ 本地发电 + 星际输电（能量枢纽）+ 射线接收站。光子源受各恒星戴森球功率的限制，P_star 正比于光度 × 球规模，可以作为外生参数输入。

### 5.2 问题 (a)：早期多期 MILP

时间分为 t=1..T 段，每段 1–3 h。

**科技解锁：**
- 二值变量 u_{τ,t} 单调不减，累计研究量 ≥ 成本时才能取 1。
- 配方和建筑的使用受其约束：x_{r,p,t} ≤ M·u_{τ(r),t}。

**储量动态：**
- B_{k,p,t+1} = B_{k,p,t} − Δt·0.94^{L_t}·m_{k,p,t}。
- 等级 L_t 是累计投入矿物利用的白糖的阶梯函数。线性化有两种办法：
  - 把各时段的等级当作外生计划；
  - 用 one-hot 二值或 SOS1 选择等级，再乘以预先算好的系数。

**终端储备约束：** 这是回答“早期用多少珍奇”的核心。它把早期使用和终局可持续性连在一起：
- 单一配方时：B_{k,T} ≥ K_k + a_k(x_end)·S(L_T)/(1−φ)；
- 分级配方时（§4.3）：B_{k,T} ≥ K_k + Σ_{n≥L_T} C(n)·0.94^(n−1)·a_k(x_n)/(1−φ)。

**目标：** 最少时间到达目标科技，或者在给定时间内累计研究量最大。珍奇用多少是优化的结果，不是目标本身。

**规模控制：** 只保留母星系和少数候选星系，按恒星系聚合星球。

### 5.3 问题 (b)：终局稳态

**目标：** 在给定 L 时 max z（白糖/min）。

**约束：**
1. 物料平衡，开采与采集上限随 L 放大（§5.1）。
2. **可持续：** a_k(x)·S(L)/(1−φ) ≤ B_k − K_k。在稳态里这条约束对配方选择的限制，和 §4 的配额是同一件事。
3. **光子与能量：** 每个白糖要 1 个反物质，所以 z ≤ 光子产率（扣除反物质路线损耗）+ 黑雾掉落的反物质。光子产率受各恒星戴森球功率限制。
   - 量级参考：笑笑估算两万糖要光子 324 GW、全厂 474 GW [笑笑 BV1wxikYXEHp，转写数字]。
   - 人造恒星的黄棒每根 72 GJ，1 根/min = 1.2 GW。按此，笑笑提到的 300 根/min 约为 360 GW。
4. **原油、气巨等可再生速率：** 对本种子（0.1 倍）这很可能是硬约束。
   - 按情形 A 每白糖 15.5 原油，两万糖/min 需要约 5.2k/s；
   - 星区初始合计只有 404.8/s，到 L80 也只有约 ×9；
   - 需要靠可燃冰、石墨烯、氢气等替代路线解决，交给 LP 选择。
5. **一次性建筑材料：** 所需总量 ≤ 剩余储量 + 黑雾的累计掉落。
6. **实用上限：** 总建筑数 ≤ N_max，物流塔数 ≤ S_max，作为 UPS 的代理。笑笑认为十万糖的最大瓶颈是 CPU [笑笑 BV1wxikYXEHp]。

**结论：**
- 给定 L 时，问题是良定的。理论上限由光子（戴森球）、可再生原料速率（随 L 增长）和黑雾掉落决定。
- 但 L 是随时间累积的状态，不能当作自由变量。
- 实际答案需要选一种写法：
  - (i) 给定 L 和 UPS/建筑上限，求 max z；
  - (ii) 在时间窗 T 内，求累计白糖最多（此时 L 内生）。

### 5.4 黑雾作为源

**建模：**
- 每个可养殖的地面基地 b 设整数或二值变量 y_b，掉落速率向量记为 d_{b,i}(lv, L)。
- 普通物品的掉落按 (1+0.04L)·clamp(资源倍率, 0.3, 2)·(1−缺乏症折减) 缩放；专属物品不受资源倍率影响 [BWIKI，Saros readme]。
- 掉落只出现在解锁等级以上（§3）。

**成本：**
- 防御塔的建筑数和电力。笑笑的做法是在基地外圈布置激光塔，每排约 10 座 [笑笑 BV1BxDQYyEfU]。
- 行星护盾和轨道炮。
- 拾取上限：每个战场分析基站拾取 8 种物品；残骸 3 分钟不拾取就消失 [BWIKI]。
- 威胁度和太空袭击，可以先按固定成本计。

**数据缺口：**
- 掉落速率没有公开的定量数据。BWIKI 只有解锁表；笑笑只说“单极磁石掉落速度还是非常慢”“超频越多掉的磁石就越多” [笑笑 BV1BxDQYyEfU, BV1wxikYXEHp]。
- 需要在游戏里实测：对一个超频基地记录 1 小时的入库量，并记下当时的黑雾等级和矿物利用等级 L。
- 可养殖基地数等于种子决定的太空巢穴数加上存档中的地面基地数；后者无法从种子得到（存疑）。

**对答案的影响：**
- **(a) 早期珍奇：** 单极磁石、光栅石变为可再生，§4 的阈值下降甚至消失。处理器、碳纳米管、粒子容器（笑笑所说“阴间三样”的主体）等中间品可以直接掉落，影响比“磁石可再生”更大。
- **(b) 终局：**
  - 核心素和物质重组器只能来自黑雾，所以黄棒供电和若干配方都依赖它。
  - 掉落的反物质能绕开 §5.3 第 3 条的光子上限。
  - 黑雾凭空产出物品，能抬高 z，抬高多少取决于实测速率、养殖规模，以及 UPS 上限。
- **规划器现状：** `data/dsp.json` 只把 df-* 专属物品列为原料。情形 G（df-* 几乎免费）与情形 F 结果相同，只能说明这些专属物品不在白糖链上，不能说明黑雾对白糖链无关。黑雾掉落的普通物品和中间品目前还不能作为来源（§6）。

## 8. 前置知识（建议学习）

1. **线性规划与对偶：** 物料平衡 LP；影子价格，即规划器的 Item values 页签。参考 Bertsimas & Tsitsiklis《Introduction to Linear Optimization》第 1–4 章。
2. **MIP 建模技巧：** big-M、用 one-hot 或 SOS1 线性化离散等级、分段线性。参考 Williams《Model Building in Mathematical Programming》。
3. **多期规划与库存模型：** 储量状态方程和终端条件。§4 的储备约束就是一种终端价值约束。
4. **几何级数：** Σ k·q^k = q/(1−q)²，由此得到 S(6) 的闭式。
5. **网络流：** 多星球运输是多商品流问题。
6. **程序化生成的确定性复现：** 种子伪随机数生成器（复刻 .NET 的 `System.Random`）、单精度浮点一致性、Simplex 噪声。可以读 DoubleUTH 的 `src/data/random.rs` 和 `planet.rs`。
7. **DSP 机制：** §3 所列的 BWIKI 页面；笑笑的珍奇和万糖视频（第 12、16–20 期）。

## 10. 存疑清单

- DoubleUTH 的“实际矿脉量”与游戏是否一致，以及它支持的游戏版本。
- 油泉枯竭下限和衰减速度随 L 变化的推论；同一矿点能否被多台矿机同时开采；启用曲速的距离。
- 研究站喷增产剂对每级所需白糖的影响。
- 黑雾掉落速率（完全没有数据）；能否由种子得到地面基地数。
- 两万糖规模的数字（45000 磁石、324/474 GW、300 黄棒/min）都来自 whisper 转写。
- §4.3 的每白糖原矿量依赖 `data/dsp.json`（0.10.29）和所设权重，不是游戏实测值。
