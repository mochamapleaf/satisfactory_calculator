# Factorio 2.0 / Space Age 品质（传奇）生产：机制、线性模型与规划器实现方案

日期 2026-11-21 · 分支 `refactor` · 验证脚本 `_过程文件/quality_lp.py`（scipy/HiGHS，`python -I quality_lp.py`）

## 0. 结论摘要

1. 品质机制在稳态下**完全线性**：把每个物品展开成 `item@q`（q = 0 普通 … 4 传奇），把每个配方按"输入品质 × 插件配置"展开成若干列（mode），产物按固定的品质转移矩阵拆分，回收机也是普通配方。回收循环只是图里的环，LP 直接求稳态，不需要马尔可夫迭代；我们的 MILP（`lp.rs`）求解核心不变。需要改的是数据展开、mode 产物向量，以及几处直接读配方输入输出的函数（§5）。另外，品质挖矿和纯流体配方（如铸造浇板）是与回收升级竞争的路线，LP 必须同时包含它们。
2. 用这个模型，`quality_lp.py` **精确复现**了两个公开结果：scottmsul/FactorioQualityOptimizer 的"传奇齿轮 79.8786 个普通输入"（以及 84.1518 的另一配置），和 wiki《Quality upcycling math》的 0.013 与电磁工厂 2.722332 %、低温工厂 4.835199 %。
3. wiki 表里化工厂、组装机 3、铸造厂三项（0.344 % / 0.586 % / 1.624 %）是把**小数**插件数（约 1.4–1.8 个品质插件）代入非线性产出公式得到的，比任何真实机器组合都高。用整数插件、允许同档混用不同配置的机器（LP），最优分别是 0.341 % / 0.583 % / 1.608 %（脚本 F 节）。
4. 笑笑meow 的经验数字：
   - "7 台普通 : 1 台高品"组装机比例，在全传奇品质 3（含回收机）的假设下，模型给 7.09:1。这个比例对插件等级很敏感：插件降到 5 % / 2.5 % 时变成 8.5 / 15.9。
   - 自回收：他多集一贯说"27:1"，但他自己说的"27K 只回收出 10 个"对应约 2700:1，与模型的 2726.9:1（2.1 数值下 2682:1）一致。"27:1"更像口头简称或口误（存疑）。
5. **版本差异必须进数据**：
   - 2.1.7 起，小行星再处理配方不许装品质插件（"星岩转转乐"失效）；小行星粉碎的碎块返还从 20 % 提到 30 %；模块效果精度改为 0.01 %。wiki 模块页因此把传奇品质插件 3 写成 6.25 %，而 2.0 是 6.2 %。
   - 我们的数据是 base 2.0.77，**不含 Space Age**：没有品质插件、回收机、铸造厂、电磁工厂、低温工厂。第一步必须先换数据。

## 1. 机制（带出处）

### 1.1 品质等级与掷骰
- 共 5 档：普通(0)、优秀(1)、稀有(2)、史诗(3)、传奇。传奇的 level 是 5，wiki 原话"legendary quality represents a 2-tier improvement over epic"。但在产出链上，传奇只比史诗高一档。出处：https://wiki.factorio.com/Quality
- 掷骰规则：机器的品质几率 q 是所有插件品质值之和。每个产物先以概率 q 升一档；升档后再以固定 10 % 的概率继续升，直到某次失败或到达传奇（Quality 页，以及 FFF-375 "each additional step has 10 times lower chance" https://factorio.com/blog/post/fff-375）。
- 由此，从第 i 档出发的转移概率是：
  - 留在原档：1−q；
  - 升 1 档：0.9q，升 2 档：0.09q，升 3 档：0.009q；
  - 超出传奇的部分全部落在传奇。例如普通→传奇是 0.001q，史诗→传奇是 q。

  wiki 教程的矩阵正是这个形式：https://wiki.factorio.com/Tutorial:Quality_upcycling_math
- 2.1 的 API 把这个规则写成 `next_probability`（第一步，乘在插件品质值上）和 `chain_probability`（默认 `clamp(next_probability*0.1,0,1)`，即后续每步的概率）。2.1.7 的改动是"Quality effect values … divided by 10"和"Multiplied quality next_probability values by 10 (to a value of 1)"，两者相互抵消，**对玩家可见的概率不变**。出处：https://lua-api.factorio.com/latest/prototypes/QualityPrototype.html （2.1.25），https://wiki.factorio.com/Version_history/2.1.0
- 品质几率的上限：wiki Quality 页没有写。survey 记为 ≥0 下限（被速度插件扣到负数时截为 0），上限**存疑**。实际最大约 8×6.2 % = 49.6 %（低温工厂），与上限无关。
- **纯流体输入的配方**本身没有品质变体，但 wiki 原话是"Any items they produce are Normal unless quality modules affect them"，也就是说**可以装品质插件**，直接产出品质固体。典型例子是铸造厂用熔融金属浇铸铁板、铜板：普通矿 → 品质板，不需要回收环。模型里这类配方只有一个输入档（0），产物按 Q(q)[0,·] 拆分。
- **品质挖矿**：采矿机可以装品质插件，挖出品质矿。论坛有开发者回复，确认这是有意设计（https://forums.factorio.com/viewtopic.php?p=651771 ，本报告没有独立打开核实，存疑）。挖矿产能没有 300 % 上限（Productivity 页）。FactorioLab `spa` 的采矿配方也没有禁用品质效果。"传奇矿 → 整条链全传奇"和"回收升级"是互相竞争的路线，LP 必须同时看到两者。
- 下面几类配方不吃品质插件或装了无效（Quality 页）：
  - 装桶/倒桶配方；
  - 产物与原料相同的配方（Kovarex、养鱼）；
  - 火箭发射井、实验室、生物实验室里装品质插件无效。
- 流体没有品质：回收机丢掉流体原料。铸造厂这类"固体 + 熔融金属"配方，产物品质只由固体原料决定，流体可以用普通矿冶炼。这就是"LDS shuffle"的基础（§1.6）。
- 产能多出的产物与本次掷出的品质相同（"the result is duplicated whenever the productivity bar completes"，https://wiki.factorio.com/Productivity）。所以在模型里可以写成"产物 ×(1+p) 再按 q 拆分"。

### 1.2 插件（2.0 数值，按普通/优秀/稀有/史诗/传奇）
| 插件 | 正面效果 | 负面效果 |
|---|---|---|
| 品质 1 / 2 / 3 | +1/1.3/1.6/1.9/2.5 %；+2/2.6/3.2/3.8/5 %；+2.5/3.2/4/4.7/**6.2** % | 速度 −5 %（各级相同） |
| 产能 1 / 2 / 3 | +4/5/6/7/10 %；+6/7/9/11/15 %；+10/13/16/19/25 % | 速度 −5/−10/−15 %，耗电 +40/60/80 % |
| 速度 1 / 2 / 3 | +20…50 %；+30…75 %；+50…125 % | 品质 −1/−1.5/−2.5 %，耗电 +50/60/70 % |

出处：https://wiki.factorio.com/Quality ，https://wiki.factorio.com/Module
- 品质只放大**正面**效果：每级 +30 %，然后向下取整，品质插件取到 0.1 %，其他插件取到 1 %。所以 2.0 的传奇品质 3 是 6.2 %，FactorioLab `spa` 数据里也存的是 0.062。
- 2.1.7 起"Module effects now have resolution of 0.01%"。wiki Quality module 3 页现在写传奇 **6.25 %**（https://wiki.factorio.com/Quality_module_3）。这个值随版本变化，必须来自数据，不能写死。按 6.25 % 和回收机 25 % 重算齿轮例子，是 78.40 个输入每个传奇（2.0 值下是 79.88）。
- 速度、耗电、污染不能低于原值的 20 %（Module 页）。
- 产能上限：配方的 `maximum_productivity` 默认 3.0，即 +300 %（https://lua-api.factorio.com/latest/prototypes/RecipePrototype.html）。wiki 说设上限"primarily done to prevent infinite resource exploits"（Productivity 页）。挖矿产能没有这个上限。
- 插件塔（beacon）只能装速度和节能插件，**不能装产能或品质插件**。分配效率按品质为 1.5/1.7/1.9/2.1/2.5，有 2 个槽，n 座塔同时作用时每座传输效率 ÷√n（https://wiki.factorio.com/Beacon）。速度插件的品质惩罚也会经塔传过去：笑笑 ep46 41:05 从品质机器上撤掉了速度塔。

### 1.4 回收机
- 平均返还"exactly 25% of the items needed to craft one item"。
- 回收配方的时间是原配方的 1/16。2.1.13 起还会按配方产物数量缩放（"scale recycle time with item result count"）。
- 若某物品没有可逆配方，回收机以 25 % 的概率返还它自己（物品"自回收"）。
- 不装品质插件时，返还物品与输入同品质。
- 流体原料全部丢失。
- 不吃任何产能科技（Productivity 页）。

出处：https://wiki.factorio.com/Recycler

### 1.5 小行星
小行星再处理（粉碎机，2 s 或 1 s）：1 个碎块返还 0.4 个同种碎块、另外两种各 0.2 个，合计 80 % 返还。2.0 时这套配方能装品质插件，就是"太空赌场 / 星岩转转乐"。**2.1.7 "Disallow quality modules to be applied to crushers with asteroid reprocessing recipes."** 同一版本把粉碎配方的碎块返还从 20 % 提到 30 %，高级粉碎从 5 % 提到 10 %（https://wiki.factorio.com/Crusher ，Version_history/2.1.0）。粉碎配方本身仍能装品质插件，因此可以产出品质矿、碳、冰。

### 1.6 LDS shuffle（铸造低密度结构）
- 铸造配方是 5 塑料 + 80 熔融铁 + 250 熔融铜 → 1 LDS，15 s，铸造厂（https://wiki.factorio.com/Casting_low_density_structure）。
- LDS 回收按标准配方（20 铜板、2 钢、5 塑料）返还 25 %：每个 LDS 返还 5 铜板、0.5 钢、1.25 塑料，耗时 15/16 s。这些数取自 FactorioLab `spa` 数据的 `low-density-structure-recycling` 配方，wiki Recycler 页没有列出 LDS。回收保持品质（Recycler 页）。
- 只要产能达到 +300 % 上限，5 塑料 → 4 LDS → 回收回 5 塑料。也就是说塑料**数量（期望值）守恒**，铜板和钢凭熔融金属（流体，无品质）凭空增加，而每一轮都在掷品质。
- 前提条件：铸造厂的槽位要全装品质插件，同时产能还要在上限。铸造厂自带 +50 %，所以 +250 % 必须全部来自 LDS 产能研究；按每级 +10 % 算是 25 级（每级 +10 % 存疑）。产能不够时，就只能在"装产能插件（q_f=0）"和"环有损耗"之间权衡。
- 模型推论：如果把传奇 LDS 也回收成传奇塑料，**每投入 1 个普通塑料，期望得到 1 个传奇塑料**，外加传奇铜板和钢作为副产（守恒推论；每轮的对角保持系数 (1−q_f)(1−q_r) < 1，所以必然收敛）。实际上还有 LP 不建模的损失：切换原料时机器的产能进度条会清零，回收返还也是随机的。
- 2.1 状态：2.1.0 版本史两部分都查过，没有关于铸造 LDS 品质的条目；2.1.7 只禁止了小行星再处理配方的品质插件。第三方 mod "No quality cheesing" 在 2.1 下的作用是"禁止铸造 LDS 配方使用品质"（https://mods.factorio.com/mod/no-quality-cheesing ），这间接说明 **2.1 原版里 LDS shuffle 仍有效（存疑，属推断）**。笑笑 ep38 转述过设计师的说法"传奇LDS循环可能会死"。

## 2. 模型：item@q 展开是一个线性（吸收马尔可夫）系统

### 2.1 记号
- 品质档 i ∈ {0,…,4}。机器有 N 个槽，其中 k 个装品质插件（每个值 q_m），其余 N−k 个装产能插件（每个值 p_m），机器自带产能 p0。则：
  - q(k) = k·q_m；
  - p(k) = min(p0 + (N−k)·p_m, 3)。
- 转移矩阵 Q(q)[i,j]：j=i 时是 1−q；i<j<4 时是 q·0.9·0.1^(j−i−1)；j=4 时是 q·0.1^(3−i)。传奇行是 Q[4,4]=1。
- **配方列**（每个配方 × 输入品质 i × 插件配置 k 一列，活动量 x_{i,k} = 每秒合成次数）：
  - 消耗第 i 档原料；
  - 产出 (1+p(k))·Q(q(k))[i,j]，j = 0…4。
- **回收列**（活动量 r_j）：
  - 消耗第 j 档产物；
  - 返还 0.25·Q(q_r)[j,m] 份原料，m = 0…4。q_r 是回收机上 4 个插件的品质和，4 个传奇品质 3 时 q_r = 0.248。
- 平衡约束：每个 `item@q` 的总产出 − 总消耗 = 外部需求（目标）或 ≥ −供应（原料）。

这正是 `lp.rs` 已有的形式：活动量 × 固定系数，线性等式/不等式。机器数 = 活动量 × 配方时间 ÷ (机器速度 × 插件速度系数)，仍然是线性的。因此**稳态品质工厂是一个 LP**，整数机器数则是 MILP，不需要任何新的求解器能力。插件组合是离散选择，但 LP 允许同一档用两种配置的机器各若干台，也就是列的凸组合，这在物理上可以实现。

### 2.2 闭式解（固定每档插件配置）
令 L[m,i] = Σ_{j<4} (1+p_i)·Q(q_i)[i,j]·0.25·Q(q_r)[j,m]，表示在第 i 档合成 1 份原料、产物回收后，回到第 m 档的原料份数。

由于品质只升不降，L 是**下三角矩阵**。稳态方程是 x = e₀ + L·x，其中 e₀ 表示每单位时间投入 1 份普通原料，所以 x = (I−L)⁻¹e₀，可以前代求解：

  x₀ = 1/(1−L₀₀)，x_m = (Σ_{i<m} L[m,i]·x_i)/(1−L_mm)（m = 1…3），x₄ = Σ_{i<4} L[4,i]·x_i

每份普通原料得到的传奇产物：

  Y = Σ_{i<4} x_i·(1+p_i)·Q(q_i)[i,4] + x₄·(1+p₄)

（传奇原料用满产能合成，p₄ = min(p0+N·p_m, 3)。）

其中对角元 L_mm = (1+p_m)(1−q_m)·0.25·(1−q_r)，它必须 < 1 循环才收敛。产能上限 300 % 和回收 25 % 的乘积恰好等于 1，这就是 wiki 说上限用来防止"infinite resource exploits"的原因。这是 wiki 公式 rᵀ(I−T)⁻¹n₀ 的显式形式，也就是吸收马尔可夫链的基本矩阵。

**特例：自回收物品**（没有可逆配方、回收返还自己，比如虫卵、U238），只有回收机。令 M = 0.25·Q(q_r)，同样前代求解。4×传奇品质 3（q_r = 0.248）时，**每 2726.9 个普通得 1 个传奇**（脚本 D 节）。

### 2.3 算例（逐步可核）：传奇齿轮
条件：组装机 3（N=4，p0=0），传奇品质 3（6.2 %）和传奇产能 3（25 %）各 2 个，回收机 4×传奇品质 3（q_r=0.248）。齿轮配方是 2 铁板 → 1 齿轮，回收返还 0.5 铁板，即 0.25 份。
- q = 0.124，p = 0.5。Q(0.124) 普通行 = (0.876, 0.1116, 0.01116, 0.001116, 0.000124)；Q(0.248) 普通行 = (0.752, 0.2232, 0.02232, 0.002232, 0.000248)。
- L₀₀ = 1.5 × 0.876 × 0.25 × 0.752 = 0.24703，所以 x₀ = 1/(1−0.24703) = 1.32808。
- 前代得 x = (1.32808, 0.18483, 0.06068, 0.01845, 0.00368)，Y = 0.012519 个传奇齿轮每份普通原料。
- 因此每个传奇齿轮需要 **79.8786 份原料 = 159.76 块普通铁板**。scottmsul README 的结果是 0.5 传奇齿轮/s 需 79.87855759632305 铁板/s，**完全一致**（https://github.com/scottmsul/FactorioQualityOptimizer ，MIT，OR-Tools LP）。
- 同一 LP 让每档自由选配置时，最优仍是"每档 2 品质 2 产能，传奇档 4 产能"，和 README 相同。把普通档改成 3 品质 1 产能，结果是 84.1518，README 的"最少插件"解是 84.15177514，同样一致。
- 机器数（传奇机器，组装机 3 速度 3.125；插件速度系数：产能 −15 %/个、品质 −5 %/个；回收机速度 1.25×0.8，配方时间 0.5/16 s）：
  - 0.5 传奇齿轮/s 的"最省原料"解约 **20.0 台**（LP 连续值）；
  - "最少机器"目标下降到 **15.5 台**，代价是铁板从 79.9/s 增到 96.3/s。

  可见目标函数不同，选出的插件配比也不同。

| 化工厂最优 | 0.344061 % | 整数 0.3412 %；小数 0.3441 % | 同上 |

表中"整数"指每档一种整数配置。允许同档混用多种配置的 LP 结果与之相同（组装机 3 也是 0.583017 %）。

wiki 对自己表里的小数行解释为"同一档用多台不同配比的机器"。但混用机器在数学上是列的凸组合，LP 已经包含了这种情况，结果仍是 0.583 %，低于 wiki 的 0.586 %。可见 wiki 的数是把小数 k 代入非线性的 (1+p(k))·Q(k·q) 得到的，现实中无法实现。差距很小（< 1 % 相对误差），不影响工程使用。上表全部数字由脚本 F 节输出。

wiki 页面上的"每传奇机器数"表也是在同样假设下算的（包括"恒定的优秀品输入"这一假设），本报告没有逐项复核：**存疑**。

### 2.5 其他闭式数字（2.0）

  - 全传奇品质 3（含回收机 24.8 %）：**7.09 : 1**；把传奇档也计入高品机器则是 6.99。

## 3. 优化的决策变量与目标

### 3.1 每台机器的插件配置 = 离散 mode
- 每个"配方 × 输入品质 × 机器类型"生成 N+1 个 mode（k = 0…N 个品质插件，其余是产能插件）。不允许产能的配方只有"全品质 / 空槽 / 速度 / 节能"几种。传奇档只需要"全产能"，因为品质插件在传奇档无效。
- 采矿配方和纯流体输入配方同样生成 k = 0…N 个品质插件的 mode，但只有输入档 0。采矿的产能不受 300 % 上限约束。
- 已有先例：Factory Solver（Factorio mod，MIT，内点法 LP，支持品质回收环，见 calculators-survey.md §1.2）和 FactorioLab（GLPK LP，支持品质）都把品质当作 LP 处理。本方案的不同之处在于整数机器数和自定义成本函数。
- 允许混装速度插件时，组合数是 C(N+2, 2)（低温工厂 8 槽时为 45）。建议默认只用"品质 + 产能"两类，速度插件作为可选项。
- 规模估算：Space Age 约 400 个配方 × 5 档 × 平均 5 个 mode ≈ 1 万列，回收配方约 2 千列。LP 没有问题；整数机器 MILP 在 microlp 上是否在时限内收敛：**存疑，需要实测**。建议品质链默认用 LP，"整数机器"作为可选项。
- 插件本身也是 `module@q` 物品，可以作为 held 物品计入预算或成本（scottmsul 的 `--module-cost` 就是这样）。一个"最少插件"目标正好对应 `CostWeights` 里新增一项插件成本。

### 3.2 插件塔
插件塔只能装速度/节能插件。对品质机器，速度塔会按传输效率扣掉品质几率，这个扣减可以在 mode 预计算里得到常数。所以插件塔是 mode 的另一维（0、4、8、12 座 × 速度 3 …），系数用 FactorioLab 数据里的 `profile` 表（survey §2.2.2）。塔的耗电按每台机器分摊。默认不给品质机器配速度塔，这与笑笑的做法一致。

### 3.3 在哪一步回收
- 每个 `item@q`（q<4）都可以选择回收或不回收：回收列就是 LP 的可选列，求解器自己决定。
- 多级链（A→B→C）中，是在中间产物 A 处回收、在最终产物处回收，还是两处都回收，同样由求解器决定。
- scottmsul 的例子显示，放开所有配方后，最优解会去"借道"地下传送带，把输入降到 47.93。
- 用户还应能把某档的回收**关掉**，比如"传奇不回收""只回收到史诗"。

### 3.4 目标
| 目标 | 现有 CostWeights 能否表达 | 说明 |
|---|---|---|
| 每个传奇产物消耗的原料最少 | 能（resources 权重） | 目标设为 `X@4`，原料设为 `ore@0` |
| 机器最少 | 能（buildings） | 回收机也算机器 |
| 功率最少 | 能（MW） | 回收机 186 kW、EM 工厂 2 MW 等，插件改变耗电 |
| 插件最少 / 插件按品质计价 | **需要新增** module 成本 | 传奇插件贵，要按品质分开计价 |
| 加权混合 | 能 | 和 scottmsul 默认"原料 1 + 插件 1"一样 |

  - 直接刷 EM 工厂：只要 5 个品质 3 就能启动；

## 5. 规划器实现计划（小步，每步可测）

已有基础：
- `rules.rs` 的 mode：目前一种插件填满所有槽，没有插件塔，也没有机器自带效果。
- `Effect.quality` 字段。
- `lp.rs` 的通用 MILP。

既定计划在 `docs/research/calculators-survey.md`：§2.2.3，以及实现顺序"插件 + 插件塔 + 研究产能 → 品质展开"。本方案沿用它的做法，在**数据层**把 `recipe@输入品质` 展开为普通配方，求解器核心不改。

但 mode 的产物依赖插件配置，所以 mode 也要能给出按品质拆分的产物向量（见第 4 步）。

1. **数据：换成 Space Age。**
   - 用 `tools/convert_factoriolab.py` 新增 `spa` 数据集（FactorioLab `public/data/spa/data.json`，2.0.77，MIT），保留 base 2.0。
   - 据 critic 核对的 `spa` 数据（本报告作者没有亲自打开）：
     - 有 279 个带 `recycling` 标记的回收配方，`disallowedEffects:["productivity"]`，时间已经 /16；自回收配方（如 `uranium-238-recycling`、`biter-egg-recycling`）返还 0.25 个自己。
     - 没有逐配方的 `allow_quality` / `maximum_productivity` 字段，限制都写在配方或机器的 `disallowedEffects` 里。
     - 机器自带产能在 `baseEffect`，品质档在顶层 `qualities`，插件塔有 `profile`。
     - 插件按品质的数值取自 `qualityRecord`，**不要用 ×1.3 现算**。
   - 2.0.77 数据仍允许 `*-asteroid-reprocessing` 装品质插件，按 2.1.7 的改动打补丁（作为版本开关）。
   - 测试：回收配方条数 > 0；EM 工厂 5 槽、+50 %。
2. **研究产能和机器自带效果**（survey 既定顺序，必须在品质之前）：
   - 每个配方加研究产能等级（如 LDS、处理器，每级 +10 %，存疑）；
   - 机器 `baseEffect` 进入 mode；
   - 总产能按配方截在 `maximum_productivity`，默认 +300 %；采矿不截。

   测试：EM 工厂空槽 mode 的 out_mult = 1.5。
3. **展开：`expand_quality(data, settings)`。**
   - 加载后生成 `item@q`（流体不展开），每个配方 r 生成 `r@i`（i = 0…最高已解锁档）：固体输入改为 `x@i`，流体输入不变。纯流体输入配方和采矿只生成 `r@0`。
   - 资源和原料按裸 id 映射：`iron-ore@0` 要能被 `data.resource()`/`resource_weight` 识别，否则不计成本。
   - 受影响的函数：`relevant()`（图剪枝，从 `x@4` 目标回溯）、`items_of()`、`build_scaled` 中的资源/供应行、`finish()`（结果 RateLines）、物流 Sankey、Item values。
   - 测试：物品数 ≈ 固体数 × 5 + 流体数；剪枝后传奇齿轮子图只含齿轮、铁板和回收配方。
4. **Mode 产物向量。**
   - 给 `Mode` 加 `outputs: Option<Vec<(String,f64)>>`，覆盖 `r.outputs × out_mult`。`lp.rs` 建平衡行、`finish()` 输出结果时都改为读 mode 的产物。
   - `tiered_modes` 对 `r@i` 生成 k = 0…N 个品质插件的 mode：q、p 按 §2.1 计算；速度按 −5 %/−15 % 等计算并截在 20 % 以上；耗电同样计算；q 截在 ≥ 0。
   - 不允许产能的配方只生成"品质 / 空 / 速度 / 节能"。
5. **回收机配方作为普通配方。**
   - 回收机只有"0…4 个品质插件"几种 mode，传奇档默认不回收（可设置）。
   - Oracle 测试：直接移植 `quality_lp.py` 的数值作为 Rust 测试。注意 `lp.rs` 里供应（supplies）成本是 0，所以要把 `iron-plate@0` 设成**带权重的资源**，或者给供应加成本，否则"最省原料"无从最小化。
     - 齿轮：79.8786（容差 1e-6），配置 [3,2,2,2] 为 84.1518；
     - wiki 度量：EM 全品质 0.01299，EM 最优 2.722332 %，低温最优 4.835199 %，组装机 3 为 0.583017 %；
     - 自回收 2726.9:1；7.09:1 比例。
6. **成本与预算。**
   - `CostWeights` 加插件成本：按 `module@q` 计价，held 数量 = 台数 × 槽数。
   - 机器品质作为全局设置（速度 ×(1+0.3·level)），先只做统一品质。
   - 默认 LP，可勾选"整数机器"。实测 microlp 在约 1 万列时的规模和时间，必要时只对品质子图做整数化。
7. **UI。**
   - 目标和输入可以选品质（默认传奇）；图标加品质角标；设置面板加"最高品质 / 插件等级与品质 / 机器品质 / 研究产能 / 回收开关"。
   - 结果表按"配方 × 品质"分组，显示每档插件配置和台数（如"普通档：2Q2P × n 台"），回收机单列。
   - 物流 Sankey 里，回收环显示为回流弧（ecbbf77 已有这个能力）。
8. **插件塔。** 在 mode 里增加速度塔的维度，用 `profile` 表计算，计入塔耗电和品质惩罚。品质机器默认不配塔。
9. **版本开关。**
   - 2.0 和 2.1 的差异来自数据：传奇品质 3 是 6.2 % 还是 6.25 %、再处理是否允许品质插件、粉碎返还 20 % 还是 30 %。不写进代码。
   - FactorioLab 是否已有 2.1 数据：**存疑**。
10. **（可选）LDS shuffle 等"守恒环"。** 产能达到上限时，L_mm 可能接近 1。测试数值稳定性：HiGHS 没有问题，microlp 需要验证。

## 6. 前置知识
- **吸收马尔可夫链**：转移矩阵分块成 [[T, R],[0, I]]，基本矩阵 N=(I−T)⁻¹ 给出每个暂态的期望访问次数，吸收概率 = N·R。本报告的 L 就是 T（下三角），传奇就是吸收态。
- **线性规划**：标准形 min cᵀx，Ax = b，x ≥ 0。生产规划中"每个物品一行、每个配方（mode）一列"；对偶变量（影子价格）就是物品的边际成本，比如"一个史诗齿轮值多少普通铁板"，项目已有 Item values 页可以直接显示。
- **凸组合**：同一档两种插件配置的机器混用，等价于两列的凸组合，LP 天然包含这种情况。把小数插件数代入非线性产出公式则不是凸组合，得到的值高于可实现值（§2.4）。
- **下三角方程组的前代求解**：品质只升不降保证了 L 是下三角，闭式解即逐行求解。
- **Factorio 机制**：插件效果相加后再截断；产能乘产物；品质掷骰只看配方开始时；流体无品质；插件塔 1/√n 衰减。
